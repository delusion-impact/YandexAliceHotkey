# История изменений

## 2.8.0

### Исправлено

- Перелистывание PDF переведено с клавиатуры на **колесо мыши**. Журнал прошлой версии показал, что синтезированные клавиши до встроенного PDF-просмотрщика не доходят вообще: после окончания озвучки лист оставался на `top=536`, а ArrowRight, PageDown, ArrowDown и Ctrl+↓ не сдвигали вид ни на пиксель (14 шагов выравнивания дали байт-в-байт ту же геометрию). События мыши просмотрщик принимает, поэтому прокрутка колесом над листом работает.
- После окончания речи Алиса сама прокручивает документ к месту чтения, и лист часто оказывается на границе двух страниц. Приложение теперь сначала выравнивает видимый лист колесом (верх у верхнего края, низ у нижнего), затем проверяет текст по OCR и, если страница не сменилась, прокручивает ещё примерно на экран.
- Убраны неработавшие клавиатурные команды перелистывания (Ctrl+↓, ArrowRight/PageDown, ArrowDown/ArrowUp) и связанное ожидание стабильности по отпечатку вида.

### Изменено

- Проверка «страница сменилась» выполняется после выравнивания: повторное чтение той же страницы исключено, а ложное срабатывание на недокрученном виде - тоже.
- Версия приложения и имя сборки обновлены до 2.8.0; README описывает перелистывание колесом.

## 2.7.0

### Исправлено

- Перелистывание страниц в циклическом режиме: вместо Ctrl+↓ используется **→** (ArrowRight; резервный вариант — **PageDown**). В PDF-просмотрщике Chromium (он же в Яндекс Браузере) Ctrl+стрелки игнорируются, поэтому Ctrl+↓ не перелистывал страницу, а прокручивал вид примерно на пол-экрана: лист оставался на границе двух страниц, геометрия не менялась, и авточтение аварийно останавливалось с сообщением «страница после Ctrl+↓ отрисована не полностью».
- Удалён приём «вниз-вверх-вниз»: он давал нулевое суммарное смещение и не мог исправить положение листа (в журнале геометрия после каждой попытки оставалась байт-в-байт одинаковой — `top=536 height=480 clientHeight=1019`).
- Выравнивание листа в окне выполняется мелкими шагами **↓/↑**: приложение прокручивает вид, пока белая область листа не попадёт в окно целиком (верх не ниже 25 % высоты окна, низ не обрезан), с ограничением числа шагов. Это устраняет «зависание на половине» и не перескакивает через страницу.

### Изменено

- При неизменившемся после перелистывания тексте страницы в журнал дополнительно пишется маркер `PAGE MARKER` с номером страницы.
- Версия приложения и имя сборки обновлены до 2.7.0.
- В README зафиксировано правило увеличивать версию при каждом изменении исходников.
- Добавлена проприетарная лицензия с запретом распространения (файл `LICENSE`).

## 2.6.0

### Добавлено

- Режим циклического чтения и перелистывания PDF по одиночному нажатию левого Shift: приложение читает видимую страницу, дожидается окончания воспроизведения Алисы по контекстному меню, переходит на следующую страницу по Ctrl+↓ и повторяет цикл.
- Проверка контекстного меню раз в 1–2 секунды для определения окончания чтения (пункт «Остановить воспроизведение» → «Озвучить Алисой»), что не требует расчёта длительности по числу символов.
- Подтверждение смены страницы по OCR: если после Ctrl+↓ распознанный текст совпадает с предыдущей страницей, цикл останавливается вместо повторного чтения той же страницы.
- Остановка цикла любым ручным действием: повторным левым Shift, нажатием клавиши (кроме самого переключателя), кнопки мыши или прокруткой колесом. Для этого установлен низкоуровневый хук мыши, а синтезированные приложением события игнорируются по флагу injected.
- Повторные попытки выделения страницы с паузами, если просмотрщик PDF ещё не успел её отрисовать, и резервный путь через UI Automation, когда OCR не находит белую область (крупные изображения, нестандартный макет).
- Проверка, что после Ctrl+↓ лист отрисован целиком (верх листа у верхней границы окна). При известном сбое, когда лист смещается лишь наполовину и «зависает», приложение повторяет навигацию «вниз-вверх-вниз».
- Маркер страницы в журнале (`auto read: PAGE MARKER folio=…`) при неудачном выделении или запуске озвучки, чтобы такие страницы (графики, картинки) можно было учесть при дальнейшем развитии алгоритма. Страница при этом не пропускается — цикл останавливается, и авточтение перезапускается пользователем вручную.
- Всплывающее уведомление в углу экрана с причиной при аварийной остановке авточтения, чтобы режим не выглядел «зависшим».

### Изменено

- Версия приложения и имя сборки обновлены до 2.6.0.

## 2.5.11

### Изменено

- Уточнён поиск белой области листа PDF: повышен порог яркости, чтобы светло-серый фон просмотрщика реже включался в границы страницы.
- Изменено геометрическое правило отбрасывания короткого заголовка в верхней правой части страницы. Оно меньше зависит от точности правой границы листа.
- Версия указывается в журнале и имени собранного приложения.

### Проверка

- Пользователь подтвердил, что базовое выделение текста на PDF-страницах работает и продолжит проверку на разнообразных страницах.
- Фильтрация колонтитулов остаётся эвристической; отдельные макеты требуют дальнейшей проверки.

## 2.5.10 и ранее

Реализован режим чтения видимого текста PDF-страницы по одиночному нажатию Ctrl, включая поиск координат текста с Windows OCR, выделение страницы, фильтрацию некоторых колонтитулов и вызов встроенной озвучки Алисы. Приложение также сохраняет режим озвучивания уже выделенного текста клавишей ё / `` ` ``.
