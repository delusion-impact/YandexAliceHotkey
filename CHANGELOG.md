# Changelog

## [1.2.0] — 2026-11-05

### Исправлено

- **Хелпер больше не сдаётся, если открылось «не то» контекстное меню.**
  В PDF-просмотрщике (воспроизводилось на файле «Фулстек тестирование.pdf»,
  416 стр.) выделение находилось, `Shift+F10` открывал меню, но пункта
  «Озвучить Алисой AI» в нём не было — и хелпер писал
  `trigger: menu opened (N items) but the target item is missing, closing menu`,
  закрывал меню и завершался, так и не запустив озвучку. Причина: флаг
  «меню открыто» выставлялся при появлении **любого** пункта, после чего
  через 1300 мс меню безусловно закрывалось без повторов. Теперь `Trigger()`
  разбит на несколько попыток (`MENU_ATTEMPTS = 3`): при отсутствии нужного
  пункта меню закрывается и попытка повторяется целиком со свежим
  `FocusOwner` + `Shift+F10`.

- **Счётчик пунктов меню больше не учитывает скрытые элементы.**
  В дереве доступности присутствуют постоянные пункты панели браузера
  (`IsOffscreen = true`), из-за чего «меню открыто» фиксировалось
  преждевременно. Теперь учитываются только видимые пункты.

- **Добавлена пауза перед повторной попыткой** (`MENU_RETRY_DELAY_MS = 250`),
  чтобы `Escape` успел закрыть старое меню до нового `Shift+F10`.

### Добавлено

- В лог пишется **состав открытого меню** (имена видимых пунктов) —
  это упростило диагностику и позволило убедиться, что нужное меню
  существует.
- В лог добавлена **версия сборки** (`v1.2.0`), чтобы сопоставлять строки
  лога с конкретным бинарником.
- Файл `DEFECTS.md` — список актуальных дефектов и их статус.

### Тесты

Регрессия успешна: обычная HTML-страница, PDF «Текст для проверки.pdf»
и PDF «Фулстек тестирование.pdf» — везде `selection found` →
`trigger: invoking 'Озвучить Алисой AI'`. На «Фулстек» удалось поймать
сбой (`count = 0`, меню не открылось) — новый ретрай восстановился
на попытке 2/3 и озвучка запустилась.

## [1.1.0] — 2026-11-04

### Исправлено

- **Выделение в iframe больше не игнорируется.** Раньше `Decide()` смотрел только на
  `AutomationElement.FocusedElement`: пользователь выделял текст внутри iframe
  (или иного вложенного документа), а фокус оставался на внешнем документе —
  выделение «не находилось» и хоткей молча пропускал клавишу
  (`decide: selection is empty, pass through`). Теперь, если у сфокусированного
  элемента выделения нет, перебираются **все** `Document`-элементы окна браузера
  (`FindAll`), и выделение ищется в каждом из них
  (`decide: selection found in doc[N] ...`).

- **Первое нажатие хоткея больше не теряется.** Chromium поднимает дерево
  доступности не сразу, и первый вызов `AutomationElement.FocusedElement` мог
  завершаться ошибкой `E_FAIL` («Нераспознанная ошибка») — программа логировала
  `decide: FocusedElement failed: ...` и выходила, не открывая меню. Теперь
  вызов повторяется до 3 раз с паузой 150 мс.

- **Контекстное меню открывается для нужного документа.** Перед `Shift+F10`
  фокус переводится в документ-владелец выделения (`FocusOwner()` →
  `SetFocus()`), иначе меню могло открываться для постороннего элемента
  (например, для внешнего документа, пока выделение внутри iframe).
  Перевод фокуса выполняется и при повторной отправке команды после
  срабатывания таймаута.

### Добавлено

- `TryGetSelection()` — проверка выделения у отдельного `Document`-элемента
  (только `Document` с поддержкой `TextPattern`).
- `NoSelectionReason()` — в лог пишется понятная причина пропуска
  («выделение пусто» или «фокус не на содержимом страницы») вместо
  обобщённого `selection is empty`.
- `Trigger()` теперь принимает документ-владелец выделения
  (`Trigger(IntPtr, AutomationElement)`).

### Поведение без изменений

- Отсутствие выделения по-прежнему означает пропуск клавиши (это не дефект).
- Ограничение README: пункт меню ищется по русским строкам, в англоязычной
  версии Яндекс Браузера срабатывание возможно только если пункт назван
  по-русски.
- Каретка (одиночный клик), PDF, страница поиска, поле ввода — корректно
  пропускаются, как и раньше.

### Тесты

Регрессионная проверка 4/4 успешна: выделение во вложенном документе при
фокусе на внешнем → «Озвучить Алисой AI»; обычная страница → меню;
каретка → пропуск; Википедия → меню. PDF и страница поиска — без
ложных срабатываний.
