# YandexAliceHotkey

Хоткей **«`` ` ``»** (та же клавиша, что `ё` на русской раскладке) для Яндекс Браузера:
выделите текст на странице и нажмите `` ` `` — включится озвучка выделенного текста Алисой
(программно активируется пункт контекстного меню «Озвучить Алисой AI»).
Повторное нажатие во время чтения нажмёт «Остановить воспроизведение».

Клавиша **не перехватывается**: без выделенного текста, при фокусе в адресной строке,
поиске или любом поле ввода символ вводится в приложение как обычно.

## Как это работает

1. Глобальный low-level keyboard hook (`WH_KEYBOARD_LL`) отслеживает нажатие `VK_OEM_3`.
   Ничего не глотает — всегда вызывает `CallNextHookEx`.
2. Если foreground-окно имеет класс `Chrome_Yandex_WidgetWin_1` и процесс `browser`,
   первое физическое нажатие (автоповтор игнорируется, debounce 1200 мс) запускает
   фоновый STA-поток.
3. Поток через UI Automation проверяет фокус: элемент `ControlType.Document`
   с непустым `TextPattern.GetSelection()`. Если выделения нет — просто выходим.
4. При выделении шлётся `Shift+F10` (контекстное меню), ищется пункт
   «Озвучить Алисой AI» (fallback: «Остановить воспроизведение») и вызывается
   `InvokePattern.Invoke()` (fallback — клик по центру пункта).
5. Таймауты и повторы: меню 3500 мс, ожидание пункта после открытия меню 1300 мс.
   Если нужного пункта в открывшемся меню нет (например, `Shift+F10` открыл
   «чужое» меню, или английская локализация страницы/браузера), меню закрывается
   через `Esc`, выдерживается пауза 250 мс и попытка повторяется целиком
   (свежий `SetFocus` + `Shift+F10`) — всего до 3 попыток (`MENU_ATTEMPTS`).
   Учитываются только **видимые** пункты меню, состав меню пишется в лог.

Браузер и его файлы **не модифицируются** — хелпер работает снаружи.

## Сборка

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Требуется только штатный .NET Framework 4.x (`csc.exe` из `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319`
+ WPF-сборки UI Automation). Вывод: `YandexAliceHotkey.exe` (~15 КБ).

## Запуск

```powershell
.\YandexAliceHotkey.exe          # обычный режим: хук вешается сразу и висит всегда
.\YandexAliceHotkey.exe --watch  # режим наблюдения (см. ниже) - рекомендуется
.\YandexAliceHotkey.exe --stop   # остановить уже запущенный экземпляр
```

Лог: `%TEMP%\yandex_alice_hotkey.log` (путь `%TEMP%` = `C:\Users\<user>\AppData\Local\Temp`).

### Режим `--watch` (рекомендуется)

Хелпер сам следит за жизненным циклом браузера:

- нет процесса `browser` → хелпер спит (проверка раз в 0.5 с), хук не установлен;
- процесс `browser` появился → хук устанавливается, хоткей работает;
- все процессы `browser` завершились → хук снимается, возврат в ожидание;
- `--stop` работает в любом состоянии.

То есть система стартует вместе с браузером и «засыпает», когда браузер закрыт —
без записи в автозагрузку и без задач планировщика.

### Автозагрузка (опционально)

Если хотите, чтобы хелпер был запущен всегда (даже до первого старта браузера):

Выполните из папки проекта (путь подставляется автоматически):

```powershell
Set-Location 'C:\Users\adm\Documents\YandexAliceHotkey'   # ваша папка проекта
$exe = (Resolve-Path .\YandexAliceHotkey.exe).Path
$ws = New-Object -ComObject WScript.Shell
$lnk = $ws.CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\YandexAliceHotkey.lnk")
$lnk.TargetPath = $exe
$lnk.Arguments = '--watch'
$lnk.WorkingDirectory = (Get-Location).Path
$lnk.Save()
```

Проверить, что ярлык указывает на существующий файл:

```powershell
$sh = New-Object -ComObject WScript.Shell
$lnk = $sh.CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\YandexAliceHotkey.lnk")
Test-Path $lnk.TargetPath   # должно быть True
```

Остановить и удалить из автозагрузки:

```powershell
.\YandexAliceHotkey.exe --stop
Remove-Item "$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\YandexAliceHotkey.lnk"
```

> Альтернатива: `install_task.ps1` в этой папке — задача планировщика, стартующая
> по событию запуска процесса `browser.exe` (Security/4688; требует прав администратора
> для включения аудита создания процессов). Режим `--watch` проще и надёжнее, задача
> оставлена как запасной вариант.

## Проверено (E2E, Яндекс Браузер 26.10.0.1854, режим `--watch`)

- запуск без браузера → «waiting for browser»; открытие браузера → хук поднят;
- выделение перетаскиванием → `` ` `` → «Озвучить Алисой AI» активирован, Алиса читает;
- повторное нажатие во время чтения → активирован «Остановить воспроизведение»;
- закрытие всех окон браузера → процессы завершены → хук снят → возврат в ожидание;
- клик без выделения (каретка) → `` ` `` пропускается, меню не открывается;
- фокус в поле ввода (поиск, адресная строка) → символ печатается в поле;
- PDF (большой файл «Фулстек тестирование.pdf», 416 стр.): если `Shift+F10`
  открыл меню без пункта Алисы — срабатывает повтор, озвучка запускается
  (проверено: восстановление на попытке 2/3).

## Ограничения

- Пункт меню ищется по русским строкам («Озвучить Алисой» / «Остановить воспроизведение») —
  работает при русской локализации браузера. На других языках меню откроется и закроется через Esc.
- Проверка выделения и вызов меню могут дать кратковременную вспышку контекстного меню (~100–300 мс).
- Клавиша срабатывает только когда активно окно браузера с классом `Chrome_Yandex_WidgetWin_1`.
- Нажатие «ё»/`` ` `` на выделенном тексте в других приложениях работает как обычно.
