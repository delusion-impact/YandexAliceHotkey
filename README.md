# YandexAliceHotkey

Windows-приложение для запуска встроенной озвучки Алисы в Яндекс Браузере. Озвучивание выполняет сам браузер; приложение выделяет текст и вызывает команду в контекстном меню.

## Горячие клавиши

- **Ctrl отдельно** — режим чтения текущей видимой страницы PDF. Перейдите к нужной странице, отпустите Ctrl, и приложение найдёт и выделит текст на странице, затем выберет команду озвучивания. Нажатие Ctrl вместе с другой клавишей не запускает чтение.
- **Shift (левый) отдельно** — режим циклического чтения и перелистывания PDF. Приложение читает видимую страницу, затем само переходит на следующую, пока не закончится текст или вы не остановите цикл. Повторное нажатие левого Shift, а также любое ручное действие (нажатие клавиши или кнопки мыши, прокрутка колесом) останавливает цикл.
- **ё** (или `` ` `` на английской раскладке) — озвучить уже выделенный текст на странице.

Горячие клавиши работают только при активном окне Яндекс Браузера. Приложение не перехватывает нажатия клавиш для других приложений.

## Запуск

Сначала соберите приложение по инструкции в разделе «Сборка», если `YandexAliceHotkey-v2.8.0.exe` ещё не создан. Запустите его перед работой с браузером. Для автоматического ожидания запуска браузера используйте режим `--watch`:

```powershell
.\YandexAliceHotkey-v2.8.0.exe --watch
```

Остановить экземпляр приложения можно командой:

```powershell
.\YandexAliceHotkey-v2.8.0.exe --stop
```

В режиме `--watch` приложение ждёт процесс `browser`, устанавливает клавиатурный перехватчик при запуске Яндекс Браузера и снимает его после закрытия браузера. По умолчанию без `--watch` перехватчик устанавливается сразу.

Журнал находится в `%TEMP%\yandex_alice_hotkey.log`.

### Запуск вместе с Windows (необязательно)

Создайте ярлык на `YandexAliceHotkey-v2.8.0.exe` в папке автозагрузки и добавьте аргумент `--watch` в свойствах ярлыка. Удалите этот ярлык, если автоматический запуск больше не нужен.

## Режим чтения PDF

Приложение рассчитано на текстовые PDF, открытые во встроенном просмотрщике Яндекс Браузера. Пользователь сам листает документ и запускает чтение на нужной странице; приложение обрабатывает видимую область текущей страницы.

Windows OCR используется для поиска строк текста и координат выделения. Озвучивается текст, выделяемый средствами браузера. На этом этапе распознавание и чтение текста внутри изображений, сканов, диаграмм и схем не поддерживается.

Колонтитулы и номера страниц отбрасываются эвристиками на основе текста и положения строк. Разные макеты страниц могут распознаваться по-разному, поэтому приложение проверяется на дополнительных книгах и страницах. Если OCR не находит безопасную область текста, используется резервный путь UI Automation.

Для запуска озвучки приложение вызывает встроенную команду Яндекс Браузера для выделенного текста. Пункт меню ищется по русскому названию («Озвучить Алисой» или «Остановить воспроизведение»); для работы требуется русская локализация соответствующего пункта меню.

## Циклическое чтение и перелистывание

Отдельный режим запускается одиночным нажатием левого **Shift**, когда активно окно Яндекс Браузера. Приложение выполняет цикл:

1. выделяет текст видимой страницы PDF и вызывает «Озвучить Алисой»;
2. раз в 1–2 секунды проверяет контекстное меню: пока виден пункт «Остановить воспроизведение» — Алиса читает; когда пункт снова стал «Озвучить Алисой», чтение закончилось;
3. выравнивает видимый лист колесом мыши: после автопрокрутки Алисы лист часто стоит на границе двух страниц, поэтому приложение прокручивает вид, пока лист не впишется в окно целиком (верх у верхнего края, низ у нижнего);
4. если текст не изменился (страница не перелистнулась), прокручивает вид колесом ещё примерно на один экран и снова выравнивает лист;
5. подтверждает смену страницы по OCR: если распознанный текст совпадает с предыдущей страницей и после повторной прокрутки, цикл безопасно останавливается (конец документа), а не читает ту же страницу повторно;
6. повторяет с шага 1.

Прокрутка выполняется именно колесом мыши, а не клавишами: встроенный PDF-просмотрщик не принимает синтезированные приложением клавиши (Ctrl+↓, →, PageDown, ↓/↑ до него не доходят), а события мыши обрабатывает.

Если просмотрщик ещё не успел отрисовать страницу, приложение делает несколько повторных попыток выделения (с паузами), а затем пробует резервный путь через UI Automation.

Страницы, которые не удаётся выделить из-за крупного графика или картинки, не пропускаются: цикл останавливается, чтобы не нарушать последовательность повествования. В журнал при этом пишется маркер с номером страницы (`auto read: PAGE MARKER folio=…`), чтобы такие страницы можно было учесть при дальнейшем развитии алгоритма; авточтение затем перезапускается пользователем вручную.

Остановить цикл можно повторным нажатием левого Shift. Так как окончание чтения и ручная остановка через меню выглядят одинаково (в обоих случаях снова виден пункт «Озвучить Алисой»), любое ручное действие — нажатие любой клавиши (кроме самого переключателя) или кнопки мыши, а также прокрутка колесом — считается остановкой всего цикла, а не переходом к следующей странице.

При аварийной остановке (не удалось выделить страницу, дождаться окончания озвучки или перейти дальше) приложение показывает всплывающее уведомление в углу экрана с причиной, чтобы режим не выглядел «зависшим». Остановка по вашему действию уведомлением не сопровождается.

Проверка меню раз в 1–2 секунды даёт небольшую паузу между страницами, но не требует расчёта длительности по числу символов и работает при разной скорости речи.

## Сборка

В Windows с .NET Framework 4.x и Windows SDK выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт создаёт `YandexAliceHotkey-v2.8.0.exe`. Для компиляции нужен `Windows.winmd` из Windows SDK и доступ к Windows Media OCR API; распознавание текста требует установленной поддержки русского языка Windows OCR.

Правило версионирования: при любом изменении исходников или документации увеличивайте версию в константе `APP_VERSION` (`YandexAliceHotkey.cs`) и имя выходного файла в `build.ps1`, чтобы имя сборки и строка версии в журнале всегда соответствовали внесённым изменениям.

## Диагностика

- `--profile-page-once` проверяет выделение текста на текущей видимой странице, не вызывая меню Алисы.
- `--read-page-once` выполняет однократное выделение и вызывает встроенную озвучку.
- В журнале ищите строки `book OCR`, `selected text body` и `trigger: invoking`, чтобы проверить этапы поиска страницы, выделения и запуска Алисы.
- Этапы циклического режима помечены строками `auto read:` (`playback confirmed`, `playback finished`, `aligning page top=…`, `page aligned to the window`, `turning the page by wheel`, `manual activity detected`, `stopped — <причина>`, `PAGE MARKER folio=…`).
- Если лист не удаётся вписать в окно, в журнале будет `could not align the page top=… bottom=… clientHeight=…`.
